---
title: Server Files
description: Access the configured Files client from Nuxt server routes and plugins.
---

Call `useServerFiles()` inside server code when you want to operate on the storage selected by `files.config.ts`.

```ts [server/api/files.get.ts]
export default defineEventHandler(async () => {
    const files = useServerFiles()
    return files.list({ prefix: 'uploads/', limit: 20 })
})
```

Nuxt auto-imports the composable for server code. It synchronously returns the native Files client; `list()` and the other storage operations are asynchronous.

## Reuse is automatic

The first call constructs the selected provider and caches the client for the current server process. Repeated calls receive the same instance, so routes do not need their own singleton or plugin.

If provider construction fails, that failure is not cached. A later request may retry after a binding or environment problem is corrected.

## Keep access on the server

`useServerFiles()` is a server runtime API. Do not import it into a Vue component or expose a general-purpose route without authorization.

For a browser UI, mount a Files SDK gateway with an explicit policy, then use the auto-imported Vue composables against that route. [Vue Integration](/usage/vue-integration) shows the connection; the [Files SDK gateway guide](https://files-sdk.dev/docs/ui/server/gateway) defines its complete security model.

## Use the native API

The returned client keeps native methods and plugin extensions:

```ts [server/api/archive.post.ts]
export default defineEventHandler(async (event) => {
    const body = await readRawBody(event)
    const files = useServerFiles()
    return files.upload('archive/request.txt', body ?? '')
})
```

For method options, bulk behavior, `StoredFile`, capabilities, and errors, use the [Files SDK API reference](https://files-sdk.dev/docs/api).
