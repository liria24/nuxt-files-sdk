---
title: Vue Integration
description: Connect Files SDK Vue composables to public or authorized file gateways.
---

The module auto-imports `useFiles`, `useFile`, `useList`, and `useSearch` from `#files-sdk/vue`. These browser composables speak to an HTTP gateway; they do not call `useServerFiles()` directly.

## Mount a gateway

Declare the endpoint in `files.config.ts`. This read-only route exposes every file in its storage, so use a dedicated storage containing only public files:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: { adapter: 'fs', config: { root: '.data/public-files' } },
    routes: [
        {
            path: '/api/files',
            operations: ['capabilities', 'list', 'head', 'search', 'download'],
        },
    ],
})
```

`nuxt.config.ts` only needs `modules: ['nuxt-files-sdk']`; standalone Nitro uses `modules: ['nuxt-files-sdk/nitro']`. Named storages require `storage: 'name'` on each route. Routes use the native `createFilesRouter` options, except `files` comes from the selected storage.

For private files and uploads, use a separate configuration with an `authorize` callback. It receives the native Files authorization context and the public Nuxt `RequestEvent`:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: { adapter: 'fs', config: { root: '.data/files' } },
    routes: [
        {
            path: '/api/files',
            operations: ['capabilities', 'list', 'head', 'search', 'upload', 'download'],
            authorize: async ({ req, event }) => {
                const { requireFilesUser } = await import('./server/auth')
                const user = await requireFilesUser(event, req.headers)
                return { keyPrefix: `users/${user.id}/` }
            },
        },
    ],
})
```

The application supplies `requireFilesUser`, accepting `RequestEvent`, and rejects unauthenticated requests there. Read the Web Request from `event.req`, the URL from `event.url`, and application state from `event.context`. Set response headers or status through `event.res`. Standalone Nitro adapts its event to the same portable contract.

The gateway forwards the available Request signal. Nuxt 4.6's native Nitro 2 Request signal is not connected to client disconnects, so closing a connection does not by itself guarantee operation cancellation.

Gateway token secrets resolve on the server at runtime: an explicit route `secret`, then `FILES_API_SECRET`, then a purpose-derived Nuxt `appSecret`. Keep the chosen root/environment secret stable across processes that share upload tokens. Standalone Nitro requires an explicit route or environment secret. Never hardcode a production secret in `files.config.ts`: source literals can enter the server bundle. The [Files SDK authorization guide](https://files-sdk.dev/docs/ui/server/authorization) explains operation gates and key scopes.

## Read from a component

```vue [app/pages/files.vue]
<script setup lang="ts">
const prefix = ref('')
const list = useList(() => ({ prefix: prefix.value }), {
    endpoint: '/api/files',
})
const selectedKey = ref<string>()
const file = useFile(selectedKey, { endpoint: '/api/files' })
const search = useSearch('*.pdf', {}, { endpoint: '/api/files' })
</script>

<template>
    <p v-if="list.isLoading">Loading files…</p>
    <ul v-else>
        <li v-for="item in list.data?.items" :key="item.key">
            <button type="button" @click="selectedKey = item.key">
                {{ item.key }}
            </button>
        </li>
    </ul>
    <p v-if="file.data">{{ file.data.key }}</p>
    <p>{{ search.data?.length ?? 0 }} PDF files</p>
</template>
```

Inputs may be refs or getters, so reads rerun when `prefix`, the selected key, or a search pattern changes. Each query returns `data`, `error`, `isLoading`, `isFetching`, and `refetch` refs.

The component above uses the public, read-only route. Use `useFiles({ endpoint: '/api/files' })` for uploads or mutations only with the authorized route. The complete composable API lives in the [Files SDK Vue guide](https://files-sdk.dev/docs/ui/client/vue).
