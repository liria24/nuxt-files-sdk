---
title: Environment Overrides
description: Select Files storage, routes, and options for development, production, tests, prerendering, and named environments.
---

`files.config.ts` uses the same environment names as Nuxt and c12: `$development`, `$production`, `$test`, `$prerender`, and `$env.<name>`. Each block can override `storage` and `routes`.

```ts [files.config.ts]
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: () => ({ bucket: process.env.R2_BUCKET! }),
        prefix: 'documents/',
        plugins: [versioning()],
    },
    routes: [{ path: '/api/files', operations: ['list'] }],
    $development: {
        storage: { adapter: 'fs', config: { root: '.data/files' } },
        routes: [{ path: '/api/files', operations: ['list', 'upload'] }],
    },
    $test: { storage: { adapter: 'memory' } },
    $production: { storage: { adapter: 'r2', config: { bucket: 'production-files' } } },
    $prerender: { storage: { adapter: 'fs', config: { root: '.data/prerender' } } },
    $env: {
        staging: { storage: { adapter: 'r2', config: { bucket: 'staging-files' } } },
    },
})
```

`nuxt dev` selects development; a normal build selects production. `nuxt build --envName staging` also selects `$env.staging` for Files. Prerendering applies production, then prerender. An explicitly selected test environment applies `$test`. Standalone Nitro selects development or production from its build mode and applies prerender during static builds.

When an override changes `adapter`, the old provider `config` is discarded. Shared Files options such as `prefix`, `plugins`, and `hooks` remain unless the override specifies them. For the same adapter, provider `config` objects merge deeply. Explicit arrays, including `plugins` and `routes`, replace the base arrays.

Named storage overrides apply by name. You can change one storage, retain others, or add an environment-only name. A config can consist solely of an environment block, but preparing it in an environment with no storage is a configuration error.

```ts [files.config.ts]
export default defineFilesConfig({
    storage: { uploads: { adapter: 'r2', config: { bucket: 'uploads' } } },
    $development: {
        storage: {
            uploads: { adapter: 'fs', config: { root: '.data/uploads' } },
            debug: { adapter: 'memory' },
        },
    },
})
```

## Migrating to v0.1

Move the previous development provider under `$development.storage`:

```ts
// Before: devStorage: { adapter: 'fs', config: { root: '.data/files' } }
// After:
$development: { storage: { adapter: 'fs', config: { root: '.data/files' } } }
```
