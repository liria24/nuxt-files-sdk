---
title: Development Storage
description: Replace only the provider during development while retaining shared storage behavior.
---

Use `devStorage` when production points at a managed service but local development should remain credential-free.

```ts [files.config.ts]
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: () => ({
            bucket: process.env.R2_BUCKET!,
        }),
        prefix: 'documents/',
        plugins: [versioning()],
        retries: 2,
    },
    devStorage: {
        adapter: 'fs',
        config: { root: '.data/files' },
    },
})
```

During `nuxt dev`, the provider comes from `devStorage`. The base storage still supplies native common options, plugins, and hooks, so local behavior stays close to production without duplicating policy.

Production uses `storage` and never falls back to `devStorage` after a failure.

Prerendering uses the production storage. Only development mode applies `devStorage`; provider `config` objects are replaced, never deep-merged.

When the override changes provider, the adapter type includes both providers. Base plugins remain available in both environments.

## Development-only storage

Omit `storage` when Files is needed only by `.dev.ts` server routes or the Files DevTools tab:

```ts [files.config.ts]
export default defineFilesConfig({
    devStorage: {
        adapter: 'fs',
        config: { root: '.data/files-devtools' },
    },
})
```

Here `devStorage` may also define common options, plugins, and hooks. It is unavailable in production; keep calls to `useServerFiles()` in development-only server files.

## Named overrides

Match overrides by storage name and include only the storages that need a local replacement:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        archive: { adapter: 'r2', config: () => ({ bucket: process.env.ARCHIVE_BUCKET! }) },
        temporary: { adapter: 'memory' },
    },
    devStorage: {
        archive: { adapter: 'fs', config: { root: '.data/archive' } },
    },
})
```

When `storage` exists, an override key that is not present in it is rejected during preparation. In that form, `devStorage` cannot replace plugins or hooks; those remain policy owned by the base storage.
