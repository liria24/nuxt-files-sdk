---
title: Development Storage
description: Replace only the provider during development while retaining shared storage behavior.
---

Use `devStorage` when production points at a managed service but local development should remain credential-free.

```ts [files.config.ts]
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: () => ({
            bucket: process.env.R2_BUCKET!,
            client: 'fetch',
        }),
        prefix: 'documents/',
        plugins: [versioning()],
        retries: 2,
    },
    devStorage: {
        adapter: 'fs',
        config: { root: '.data/files' },
    },
})
```

During `nuxt dev`, the provider comes from `devStorage`. The base storage still supplies `prefix`, `plugins`, `hooks`, `retries`, and `timeout`, so local behavior stays close to production without duplicating common options.

Production strips `devStorage` from the server bundle and generates only the production provider import. A production construction or operation failure never falls back to the development provider.

## Development-only storage

Omit `storage` when Files is needed only by `.dev.ts` server routes or the Files DevTools tab:

```ts [files.config.ts]
export default defineFilesConfig({
    devStorage: {
        adapter: 'fs',
        config: { root: '.data/files-devtools' },
    },
})
```

Here `devStorage` is a complete `StorageConfig`, so it may define plugins, hooks, prefix, retries, and timeout. The development server installs the registry normally. Production installs no Files runtime plugin or provider import; keep every call to `useServerFiles()` in development-only server files.

## Named overrides

Match overrides by storage name and include only the storages that need a local replacement:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        archive: { adapter: 'r2', config: () => ({ bucket: process.env.ARCHIVE_BUCKET!, client: 'fetch' }) },
        temporary: { adapter: 'memory' },
    },
    devStorage: {
        archive: { adapter: 'fs', config: { root: '.data/archive' } },
    },
})
```

When `storage` exists, an override key that is not present in it is rejected during preparation. In that form, `devStorage` cannot replace plugins or hooks; those remain policy owned by the base storage.
