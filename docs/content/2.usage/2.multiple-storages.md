---
title: Multiple Storages
description: Configure named storages and make the target explicit at every server call.
---

Use named storage when one application owns distinct storage domains, such as uploads and an archive.

```ts [files.config.ts]
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        archive: {
            adapter: 'fs',
            config: { root: '.data/archive' },
            plugins: [versioning()],
        },
        uploads: {
            adapter: 'fs',
            config: { root: '.data/uploads' },
        },
    },
})
```

Pass the name at the call site:

```ts [server/api/files.get.ts]
export default defineEventHandler(async () => {
    const uploads = useServerFiles('uploads')
    const archive = useServerFiles('archive')

    return {
        uploads: await uploads.list(),
        versions: await archive.versions('report.pdf'),
    }
})
```

There is no implicit default in a named configuration. Calling `useServerFiles()` without a name fails type checking and runtime validation. Unknown names fail the same way. This makes the storage boundary visible in every route.

Each named client is constructed and memoized independently. Accessing `uploads` does not initialize `archive` or resolve its credentials.

Use `syncFiles()` or `transferFiles()` for native Files SDK bulk operations. Both are server auto-imported and accept configured names or existing `Files` instances:

```ts [server/tasks/archive.ts]
await syncFiles('uploads', 'archive', { compare: 'size', prune: true })
await transferFiles('archive', 'uploads', { overwrite: false })
```

These functions pass their options directly to Files SDK. Review the native `prune` behavior before enabling deletion.

## Browser gateways

Prefer one gateway route per storage when their authorization policies differ. The client then selects storage by endpoint rather than by sending a trusted-looking storage name:

```ts [app/pages/files.vue]
const uploads = useFiles({ endpoint: '/api/uploads' })
const archive = useFiles({ endpoint: '/api/archive' })
```

The gateway itself is a native Files SDK concern; see [Multiple buckets](https://files-sdk.dev/docs/ui/server/multiple-buckets) for the policy trade-offs.
