---
title: Files Configuration
description: Types, defaults, and effects for files.config.ts.
---

Create `files.config.ts` with `defineFilesConfig()` from `nuxt-files-sdk/config`.

## Single storage

**Type:** `{ storage: StorageConfig }`
**Access:** `useServerFiles()`

```ts [files.config.ts]
export default defineFilesConfig({
    storage: { adapter: 'memory' },
})
```

## Named storage

**Type:** `{ storage: Record<string, StorageConfig> }`
**Access:** `useServerFiles(name)`

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        uploads: { adapter: 'memory' },
        archive: {
            adapter: 'fs',
            config: { root: '.data/archive' },
        },
    },
})
```

Named mode always requires a name, even when only one name is configured.

## `routes`

**Type:** `FilesRoute[]` (optional)

Each route needs a static absolute `path`. A named storage route also needs its fixed `storage` name. Other options, including `operations`, `authorize`, and `secret`, follow the native [Files SDK gateway](https://files-sdk.dev/docs/ui/server/gateway). The authorization callback receives `{ req, event, operation, ... }`, where `event` is the current Nitro `H3Event`. Without `routes`, no application gateway is registered. Without `operations` or `authorize`, the native router only answers `capabilities`.

## `StorageConfig`

| Field      | Type                                     | Default            | Effect                                        |
| ---------- | ---------------------------------------- | ------------------ | --------------------------------------------- |
| `adapter`  | `ProviderSlug` or adapter factory        | required           | Selects a built-in or custom adapter.         |
| `config`   | provider options or synchronous resolver | provider-dependent | Supplies native provider options.             |
| `plugins`  | `FilesPlugin[]` or resolver              | `[]`               | Extends the native client in array order.     |
| `hooks`    | `FilesHooks`                             | none               | Registers native lifecycle hooks.             |
| `prefix`   | `string`                                 | none               | Scopes operations under a key prefix.         |
| `readonly` | `boolean`                                | `false`            | Blocks every write operation.                 |
| `receipts` | `boolean \| { sha256?: boolean }`        | `false`            | Adds provenance receipts to mutation events.  |
| `retries`  | `number \| { max; backoff? }`            | native default     | Configures provider retries and backoff.      |
| `signal`   | `AbortSignal`                            | none               | Supplies a default cancellation signal.       |
| `timeout`  | `number`                                 | native default     | Sets the per-attempt timeout in milliseconds. |

Provider option fields and operational semantics are defined by the [Files SDK API](https://files-sdk.dev/docs/api).

Use a built-in slug such as `adapter: 'r2'` for native providers. A custom Files SDK adapter factory can be passed directly; its `config` argument and returned adapter type are preserved. Configuration objects are the normal form. Use a synchronous `config: () => ({ ... })` resolver only for values available at runtime, such as bindings, runtime configuration, or custom resources. Provider environment variables do not need a resolver.

## Environment blocks

You can add `$development`, `$production`, `$test`, `$prerender`, and `$env` blocks. Each accepts the same `storage` and `routes` fields as the base config. Use `$env: { staging: { ... } }` for a named environment.

If storage is configured only for other environments, Files integration is inactive in the current environment. An empty config or invalid active storage is an error.

An adapter change replaces provider `config` but retains unspecified common Files options. The same adapter permits deep merge of `config` objects. Explicit arrays, including `plugins` and `routes`, replace the base arrays. Named storage merges by name and may add names available only in that environment. See [Environment Overrides](/usage/environment-overrides) for examples.
