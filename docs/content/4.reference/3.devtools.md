---
title: DevTools
description: Development-only storage inspection, read/write controls, and production boundaries.
---

The module adds a **Files** tab to Nuxt DevTools when all three conditions are true:

1. Nuxt is running in development.
2. Nuxt DevTools is enabled.
3. `files.devtools` is not `false`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['nuxt-files-sdk'],
    devtools: { enabled: true },
})
```

Authenticated Nuxt DevTools users can read and write files by default. Set `files.devtools.write` to `false` for read-only access. Use a dedicated `$development.storage`:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: { adapter: 'memory' },
    $development: { storage: { adapter: 'fs', config: { root: '.data/files-devtools' } } },
})
```

The Files panel shows storages selected for the active development environment and lets you browse, download, upload, and delete files.

DevTools Diagnostics and Messages help troubleshoot configuration and file-operation failures.

Nuxt DevTools v4 adds these command-palette entries:

- **Files: Open** opens the Files dock.
- **Files: Refresh** reloads storage information and the current file listing.
- **Files: Copy Diagnostics** copies the currently displayed diagnostics.

File listings show up to 1,000 entries per page. Use **Next** and **Previous** to move between pages. Changing storage or folder, refreshing, or completing a write returns to the first page. Refresh also reloads provider capabilities.

Authorize your browser in Nuxt DevTools before using Files. With DevTools v3, refresh the Files panel after authorization.

The Files panel is available only during development.

::warning
Write access operates with the configured development storage's authority. Never point it at repository content or a shared production bucket.
::
