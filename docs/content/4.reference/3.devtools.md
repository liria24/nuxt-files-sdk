---
title: DevTools
description: Development-only storage inspection, read/write controls, and production boundaries.
---

The module adds a **Files** tab to Nuxt DevTools when all three conditions are true:

1. Nuxt is running in development.
2. Nuxt DevTools is enabled.
3. `files.devtools` is not `false`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['nuxt-files-sdk'],
    devtools: { enabled: true },
})
```

Read and write access is the default. To limit the browser to inspection, set `files.devtools.write` to `false`. In either mode, pair it with a confined `devStorage`:

```ts [files.config.ts]
export default defineFilesConfig({
    devStorage: {
        adapter: 'fs',
        config: { root: '.data/files-devtools' },
    },
})
```

The Files panel keeps runtime state local to the Nitro worker: storage names, adapter names, plugin names, initialization state, and the active source come from the same registry used by `useServerFiles()`. File listing and mutations continue to use the Files SDK client and Nitro gateway rather than DevTools RPC.

Configuration and integration failures also appear in DevTools Diagnostics with a stable `NUXT_FILES_*` code and a troubleshooting hint. Upload, delete, storage initialization, and gateway failures are retained in DevTools Messages; routine loading and successful operations stay in the Files panel status.

Nuxt DevTools v4 adds these command-palette entries:

- **Files: Open** opens the Files dock.
- **Files: Refresh** reloads the registry snapshot and current listing.
- **Files: Copy Diagnostics** copies the currently displayed diagnostics.

The snapshot never includes provider configuration, credentials, or file contents.

The internal UI, snapshot route, and file-operation route are registered only by `nuxt dev`. They are absent from production output. These routes are implementation details and must not be used as an application API.

::warning
Write access operates with the configured development storage's authority. Never point it at repository content or a shared production bucket.
::
