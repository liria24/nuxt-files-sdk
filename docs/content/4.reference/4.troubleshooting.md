---
title: Troubleshooting
description: Resolve configuration, type, provider, DevTools, and deployment problems.
---

## Files is not configured

Confirm that `nuxt-files-sdk` is in `modules`, `files.config.ts` exists at the configured path, and the code runs in a Nitro server context. Standalone Nitro must register `nuxt-files-sdk/nitro` and import `useServerFiles` from `nuxt-files-sdk/runtime`.

## A storage name is rejected

Single storage uses `useServerFiles()` with no argument. Named storage always uses `useServerFiles('name')`. Run `nuxt prepare` or `nuxt typecheck` after changing names.

## A provider cannot be constructed

Check the provider's required options, environment variables, optional packages, and runtime support in the [Files SDK provider reference](https://files-sdk.dev/docs/providers). Configuration resolvers must return synchronously. The module preserves the native error and does not fall back to another provider.

The module groups confirmed missing or incompatible dependencies by the selected storage or public SDK entry. Identical problems are not repeatedly logged during development. Dynamic resolvers, custom aliases, and dependencies needed only for an unused operation remain quiet; open **Dependency details** in the Files panel to inspect them. The module does not install packages or replay failed operations.

Development reevaluates configuration imports and dependency manifests/lockfiles. When a configuration edit is invalid, generated application gateways return 503 until a valid configuration has loaded, so a previous authorization callback cannot keep accepting requests. Fix the configuration and wait for the development server to rebuild.

## Types are missing

Run the application's native preparation step before a standalone TypeScript invocation:

```bash [Terminal]
bunx nuxt prepare
bunx nuxt typecheck
```

For standalone Nitro, run your project's build and typecheck scripts.

## The Files tab is missing

Use `nuxt dev`, enable Nuxt DevTools, and make sure `files.devtools` is not `false`. The tab is intentionally unavailable in preview and production servers.

## Browser operations return forbidden

Vue composables require an application-owned Files SDK gateway. The router denies operations by default. Enable only the operations you need, and authorize access to private files or write operations. See [Vue Integration](/usage/vue-integration) and the [Files SDK authorization guide](https://files-sdk.dev/docs/ui/server/authorization).

## Local files disappear after deployment

The deployment probably has an ephemeral filesystem. Choose persistent storage supported by that environment; `fs` and `memory` are useful local defaults, not universal production stores.
