---
title: Plugins & Hooks
description: Add native Files SDK plugins and observe their lifecycle through typed Nitro hooks.
---

Use Files SDK plugins when a storage needs capabilities such as version history. Configure them on the storage so every `useServerFiles()` caller receives the same extended client.

```ts [files.config.ts]
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
        plugins: [versioning()],
    },
})
```

Import plugins directly from Files SDK. Use the [Files SDK plugin reference](https://files-sdk.dev/docs/plugins) for each plugin's options and added methods.

Plugins that need another storage's adapter can use a resolver. `storage(name)` constructs and caches that adapter when the client first initializes; it does not construct the other storage's Files client.

```ts [files.config.ts]
import { tiering } from 'files-sdk/tiering'
import { versioning } from 'files-sdk/versioning'

export default defineFilesConfig({
    storage: {
        archive: {
            adapter: 'fs',
            config: { root: '.data/archive' },
        },
        uploads: {
            adapter: 'fs',
            config: { root: '.data/uploads' },
            plugins: ({ storage }) => [
                versioning(),
                tiering({
                    cold: storage('archive'),
                    route: ({ key }) => (key.startsWith('archive/') ? 'cold' : 'hot'),
                }),
            ],
        },
    },
})
```

`useServerFiles('uploads')` includes the plugins' added methods in its type. Circular storage dependencies fail during initialization.

## Observe operations in Nitro

The integration forwards native lifecycle events into Nitro's hook system:

```ts [server/plugins/files-events.ts]
export default defineNitroPlugin((nitroApp) => {
    nitroApp.hooks.hook('files:error', ({ event, storage }) => {
        console.error('Files operation failed', {
            type: event.type,
            storage,
        })
    })
})
```

Available hooks are `files:action`, `files:error`, and `files:retry`. Their payload contains the native Files SDK event plus the storage name when named storage is used.

Hooks declared inside `files.config.ts` still run as native Files SDK hooks. User hooks run before the Nitro bridge, and a hook rejection does not replace the result of the underlying file operation.
