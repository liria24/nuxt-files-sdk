Choose an adapter supported by your deployment environment. See the [Files SDK provider reference](https://files-sdk.dev/docs/providers) for provider options and operation behavior.

## Configure the production provider

Keep secrets in the deployment environment. Native Files SDK provider environment variables are read when the storage is first used:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: {
            bucket: 'uploads',
            client: 'fetch',
        },
    },
})
```

Use `config: () => ({ ... })` only when an option, such as a runtime binding, is unavailable while loading the config module. The resolver must be synchronous and runs on the first call to `useServerFiles()` for that storage.

Custom Files SDK adapter factories can be passed directly:

```ts [files.config.ts]
import { myAdapter } from './server/adapters/my-adapter'

export default defineFilesConfig({
    storage: {
        adapter: myAdapter,
        config: { endpoint: 'https://example.com' },
    },
})
```

The factory and its options retain their types.

## Install provider dependencies

Some providers need an optional SDK in the application that uses them. Follow the provider page's install instructions and add that package to the deployed application, not to `nuxt-files-sdk` itself.

On Cloudflare Workers, `r2`, `minio`, and `rustfs` use fetch by default. Install the AWS SDK if you explicitly select its client.

## Check the runtime constraints

- `memory` is process-local and loses data on restart.
- `fs` needs a persistent, writable filesystem. Many serverless filesystems are ephemeral or read-only.
- Cloud providers need outbound network access and secrets configured in the deployment environment.
- A provider's runtime and package requirements remain authoritative in its [Files SDK documentation](https://files-sdk.dev/docs/providers).

If a provider fails, Files SDK returns its error and does not switch to another storage automatically.
