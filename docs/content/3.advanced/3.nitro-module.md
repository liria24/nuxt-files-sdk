---
title: Nitro Module
description: Use Files SDK in a standalone Nitro application.
---

Use `nuxt-files-sdk/nitro` for a standalone Nitro 2 or Nitro 3 server. The integration retains Nitro's native preparation, plugin lifecycle, aliases, externals, and hook wiring without requiring a Nuxt application.

```ts [nitro.config.ts]
export default defineNitroConfig({
    modules: ['nuxt-files-sdk/nitro'],
})
```

```ts [files.config.ts]
import { defineFilesConfig } from 'nuxt-files-sdk/config'

export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
    },
    routes: [
        {
            path: '/api/files',
            operations: ['capabilities', 'list'],
        },
    ],
})
```

Set `FILES_API_SECRET` in the server environment before running a gateway, or set a route `secret` from a runtime environment value. Standalone Nitro has no Nuxt `appSecret` fallback. Do not put production secret literals in source code: they can be compiled into deployment output.

Nitro registers the `/api/files` gateway. This example allows public file listings; add authorization before serving private files. For other server routes, import the runtime explicitly because Nuxt's server auto-imports are not available:

```ts [routes/files.ts]
import { useServerFiles } from 'nuxt-files-sdk/runtime'

export default defineEventHandler(async () => {
    const files = useServerFiles()
    return files.list()
})
```

Run your project's Nitro build and typecheck scripts. Nitro plugins can also use the `files:action`, `files:error`, and `files:retry` hooks.

Gateway authorization receives the public `RequestEvent` contract: `req`, `url`, `context`, and `res`. The Nitro adapter preserves the available Web Request signal and applies portable response changes. Cancellation on client disconnect depends on the native server transport; signal forwarding alone does not establish it.

SDK imports use `#files-sdk` and `#files-sdk/*` in standalone projects too. Nitro 2 receives the generated type paths through its preparation hook. In Nitro 3, include the generated configuration after building:

```json [tsconfig.json]
{
    "extends": ["nitro/tsconfig", "./node_modules/.nitro/nuxt-files-sdk/tsconfig.json"]
}
```

Keep your application's explicit Nitro and TypeScript type dependencies. Nuxt itself is not required.

Standalone Nitro applies `$development` during development, `$production` for a normal build, and `$production` followed by `$prerender` for a static build. Import `defineFilesConfig` from `nuxt-files-sdk/config` explicitly when it is not provided by your application tooling.

The Vue composables and Nuxt Files SDK DevTools are Nuxt integrations. Add `authorize` to a gateway route before allowing private files or browser mutations; the [Files SDK authorization guide](https://files-sdk.dev/docs/ui/server/authorization) describes the native rules.
