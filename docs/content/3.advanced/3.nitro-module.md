---
title: Nitro module
description: Install the same storage registry, runtime client, generated types, and hooks without Nuxt.
---

Use the Nitro entrypoint when the application is a standalone Nitro server. It shares the integration used by the Nuxt module but does not install Nuxt or Vue features.

```ts [nitro.config.ts]
export default defineNitroConfig({
    modules: ['nuxt-files-sdk/nitro'],
})
```

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
    },
})
```

Standalone routes import the runtime explicitly because Nuxt's server auto-imports are not present:

```ts [routes/files.ts]
export default defineEventHandler(async () => {
    const files = useServerFiles()
    return files.list()
})
```

Run the native Nitro `prepare`, `typecheck`, and `build` commands for generated declarations and production output. The same `files:action`, `files:error`, and `files:retry` hooks are available to Nitro plugins.

The Vue composables and Nuxt Files SDK DevTools are Nuxt integrations. A standalone Nitro application can expose a Files SDK gateway explicitly; follow the [Files SDK Nitro guide](https://files-sdk.dev/docs/ui/server/nitro) and apply authorization before allowing browser mutations.
