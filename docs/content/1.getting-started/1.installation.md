This guide uses the filesystem adapter, so you can try it without cloud credentials.

The stable Nuxt integration requires Nuxt 4.6 or newer in the supported Nuxt 4 range. Standalone Nitro 2 and Nitro 3 are also supported. Published Nuxt 5 prereleases and `@nuxt/vite-server` are experimental targets; see the capability limits below.

## Install and register the module

::code-group

```bash [npm]
npx nuxt module add files-sdk
```

```bash [pnpm]
pnpm dlx nuxt module add files-sdk
```

```bash [bun]
bunx nuxt module add files-sdk
```

```bash [yarn]
yarn dlx nuxt module add files-sdk
```

::

The command installs `nuxt-files-sdk` and adds it to `modules` in `nuxt.config.ts`. For standalone Nitro, follow [Nitro Module](/advanced/nitro-module).

Nuxt Files SDK owns its Files SDK dependency, so no separate SDK installation is needed. Import SDK features through `#files-sdk` and its public subpaths, such as `#files-sdk/versioning` or `#files-sdk/vue`. These aliases also work in `files.config.ts` and always select the module's SDK, even when the application or a Layer installs another version.

Create `files.config.ts` and add a read-only API route. The Nuxt configuration below is the result of running the command:

::code-tree{defaultValue="files.config.ts", expandAll=true}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['nuxt-files-sdk'],
})
```

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
    },
})
```

```ts [server/api/files.get.ts]
export default defineEventHandler(async () => {
    const files = useServerFiles()
    return files.list({ limit: 20 })
})
```

::

Start the development server with `npm run dev` (or your package manager's equivalent), then open `http://localhost:3000/api/files`. An empty storage returns a response with `items: []`. This route lists files without changing them; protect it before storing private files.

## Manual installation

You can also install the package directly:

::code-group

```bash [npm]
npm install nuxt-files-sdk
```

```bash [pnpm]
pnpm add nuxt-files-sdk
```

```bash [bun]
bun add nuxt-files-sdk
```

```bash [yarn]
yarn add nuxt-files-sdk
```

::

Then add `'nuxt-files-sdk'` to `modules` in `nuxt.config.ts`, as shown above, and create the storage configuration and API route.

## Move beyond local storage

Replace `fs` with the provider your deployment supports, install that provider's optional peer dependencies, and follow its setup page in the [Files SDK provider reference](https://files-sdk.dev/docs/providers).
Keep a local override with [Environment Overrides](/usage/environment-overrides) when production credentials should not be required on a developer machine.

Dependency diagnostics suggest an install command for confirmed problems. They do not install packages or prompt during preparation. Unknown runtime conditions and dependencies for unused operations remain quiet.

## Server builder capabilities

- Nuxt with Nitro: server runtime, generated gateways, Files DevTools, and native Nitro hooks
- Standalone Nitro 2/3: server runtime, gateways, and native hooks; see [Nitro Module](/advanced/nitro-module)
- Published Nuxt 5 prereleases: experimental coverage of real build, gateway HTTP, and development routes using the distributed package
- Vite server: experimental basic Files SSR coverage. Generated gateways fail preparation; Files DevTools and Nitro hooks are unavailable

Experimental coverage does not establish support for a future stable release. Check the package compatibility range and CI fixture manifests when choosing a version.
