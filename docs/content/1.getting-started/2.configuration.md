---
title: Configuration
description: Understand the module options in nuxt.config.ts and storage settings in files.config.ts.
---

Nuxt Files SDK separates framework setup from storage setup.

## Register framework options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['nuxt-files-sdk'],
    files: {
        config: 'files.config.ts',
        devtools: true,
    },
})
```

The `files` key controls the configuration path and DevTools integration. Most projects can omit it because these are the defaults. See [Module Options](/reference/module-options) for the compact option table.

## Define storage separately

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
        prefix: 'uploads/',
        retries: 2,
        timeout: 10_000,
    },
})
```

`defineFilesConfig()` provides type checking for storage names, provider options, and plugins. Restart the development server after changing storage names or providers.

Use `$development`, `$production`, `$test`, `$prerender`, or `$env` to override storage and routes for an environment. `--envName staging` selects `$env.staging` in both Nuxt and Files. See [Environment Overrides](/usage/environment-overrides).

Add `routes` in `files.config.ts` to register a Files SDK HTTP gateway. See [Vue Integration](/usage/vue-integration) for a read-only route and an authorization example.

Provider options belong under `config`. The object form above is the usual choice. For values available only at runtime, use a synchronous resolver:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: () => ({
            bucket: 'uploads',
            endpoint: process.env.RUNTIME_ENDPOINT!,
            client: 'fetch',
        }),
    },
})
```

The function runs only when `useServerFiles()` first constructs this storage. It must return immediately; an async resolver is rejected by types and at runtime. Native provider environment variables need no resolver.

::note
Files SDK environment variables also accept a `NUXT_` prefix—for example `R2_ACCOUNT_ID` or `NUXT_R2_ACCOUNT_ID`. Native keys and aliases take precedence.
::

Use [Files Configuration](/reference/files-configuration) for the full module-owned shape. Provider-specific fields remain in the [Files SDK provider reference](https://files-sdk.dev/docs/providers).
