---
title: Configuration
description: Understand the module options in nuxt.config.ts and storage settings in files.config.ts.
---

Nuxt Files SDK separates framework setup from storage setup.

## Register framework options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['nuxt-files-sdk'],
    files: {
        config: 'files.config.ts',
        devtools: true,
    },
})
```

The `files` key controls the configuration path and DevTools integration. Most projects can omit it because these are the defaults. See [Module Options](/reference/module-options) for the compact option table.

## Define storage separately

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'fs',
        config: { root: '.data/files' },
        prefix: 'uploads/',
        retries: 2,
        timeout: 10_000,
    },
})
```

`defineFilesConfig()` is an identity helper: it does not construct a provider. Its job is to keep literal storage names, provider-specific configuration, and plugin extensions available to generated TypeScript declarations.

Provider options belong under `config`. They may also come from a synchronous function when runtime bindings or environment values are required:

```ts [files.config.ts]
export default defineFilesConfig({
    storage: {
        adapter: 'r2',
        config: () => ({
            bucket: process.env.R2_BUCKET!,
            client: 'fetch',
        }),
    },
})
```

The function runs only when `useServerFiles()` first constructs this storage. It must return immediately; an async resolver is rejected by types and at runtime.

::note
Files SDK provider variables keep their native names. When a provider declares an environment key, the module also accepts its `NUXT_` alias during construction—for example `R2_ACCOUNT_ID` or `NUXT_R2_ACCOUNT_ID`. Native keys and aliases win, and temporary aliases are removed after construction.
::

Use [Files Configuration](/reference/files-configuration) for the full module-owned shape. Provider-specific fields remain in the [Files SDK provider reference](https://files-sdk.dev/docs/providers).
